## Implemented repairs

| Finding | Trigger before the repair | Result after the repair |
|---|---|---|
| OFFLINE-LOSS-1 | A post is enqueued while a sync request awaits its reply. Replacing the old queue snapshot silently loses it. | Fold replies into the current queue; late posts survive and drain. Late answers resolve their parent IDs. Ban responses reject the current sendable queue and count only newly rejected items. |
| OFFLINE-LOSS-2 | Durable storage already has an old value, and the next write fails because storage is full. Reading prefers that stale value over the newest memory state. | Keep memory authoritative until a successful write; preserve failed clears and cache successful reads for read failures. Duplicate enqueue retries persistence rather than claiming a durable save. |
| OFFLINE-SHELL-1 | First offline reload finds cached HTML but no JavaScript bundle, leaving a blank app. | Installation discovers and precaches Vite's hashed JS/CSS; runtime retains successful same-origin static assets and supports offline shell fallback. Fetch/XHR/API calls and cross-origin resources bypass the cache. |
| OFFLINE-COMPOSE-1 | Reopening offline makes the feed read fail, hides the existing Ask button, and loses the topic slugs held only in memory. | Keep the existing Ask control available; retain previously fetched public slug/label reference data and refresh it online. The server remains authoritative when the queued post eventually syncs. |

  source CI does not close T62's historical live-deployment findings.
- **Offline reference data needs prior online fetch.** A device that has never fetched
  topics still displays the existing loading error rather than inventing a catalogue.
  Cached slugs may become inactive; the server will explicitly validate/refuse them at sync.
- **Memory fallback is only for the current run.** When storage stays full, closing the
  app can still lose unsaved memory-only data; existing honest unsaved messaging remains.
  This repair does not implement atomic multi-tab storage or cross-device draft sync.
- **Shell caching assumes public static HTML/assets.** Vite's `Vary: Origin` was
  reproduced in Chromium; static cache lookup handles that mismatch. Bump the shell
  cache version on shell releases. Do not serve personalized documents through this
  cache policy without a separate reviewed design.
